Algorithm Role Best Case Average Case Worst Case Space Code-Level Loop & Operation Justification
Bubble Sort (Primary Sort) O(n) O(n²) O(n²) O(1) In-Place Outer loop runs n-1 times; inner loop performs n(n-1)/2 adjacent comparisons. With a bool swapped flag, an already-sorted array exits after 1 pass (n-1 comparisons, 0 swaps). Each swap requires 3 object assignments.
Insertion Sort (Alternative Sort) O(n) O(n²) O(n²) O(1) In-Place Iterates i = 1..n-1, shifting elements right only while records[j].studentID > key.studentID. Highly adaptive on partially sorted attendance logs; performs single shifts instead of full 3-step swaps.
Linear Search (Primary Search) O(1) O(n) O(n) O(1) In-Place Single for (i = 0; i < recordCount; i++) loop. Best case finds target at index 0 (1 comparison). Worst case scans all n records when target is at n-1 or absent. Works directly on unsorted arrays.
Binary Search (Alternative Search) O(1) O(log₂ n) O(log₂ n) O(1) Iterative Halves search interval [low, high] every iteration via mid = (low + high) / 2. At N = 1,000, requires at most ⌈log₂(1000)⌉ = 10 comparisons, but strictly requires a sorted array first.

Section 3 Point 5 — Critical Engineering Discussion

Which Sorting & Searching Methods are Most Suitable for SATS and Why?

1. Why Insertion Sort Beats Bubble Sort for SATS

In a university classroom (N = 50–200 per session, N = 1,000 cumulative), attendance records are often appended in batches or maintained in near-sorted order after previous lecturer exports. While both are O(n²) worst-case, Insertion Sort executes ~50% fewer comparisons on random data and performs single-assignment shifts rather than 3-assignment swaps, running nearly 2× faster at N = 1,000.

2. The Binary Search Pre-Sorting Trade-Off

When students scan QR codes live during class, records are appended chronologically by arrival time—meaning records[] is unsorted by Student ID. Performing a single lookup on unsorted data using Linear Search costs at most O(n) = 1,000 comparisons, whereas sorting first just to run Binary Search costs O(n²) ≈ 500,000 operations!

3. Hybrid Recommendation for SATS

Use Linear Search during live QR check-in (UC03) to quickly check for duplicate scans in the active session without disturbing arrival order. Once the session closes and the Lecturer sorts the roster via Insertion Sort (UC05), set an isSortedByID = true flag and switch UC04 to Binary Search (≤ 10 comparisons at N = 1,000).

AttendanceSystem_Assignment1.cpp (Core Sorting & Searching Methods) C++17 Standard 
// Task 3: Fixed-Size Array of Objects inside AttendanceSystem Controller
const int MAX_RECORDS = 2000;
AttendanceRecord records[MAX_RECORDS];
int recordCount = 0;
bool isSortedByStudentID = false;

// Task 5 (Primary): Bubble Sort with Early-Exit & Empirical Counters
void bubbleSortByStudentID(long &comparisons, long &swaps) {
    comparisons = 0; swaps = 0;
    for (int i = 0; i < recordCount - 1; i++) {
        bool swapped = false;
        for (int j = 0; j < recordCount - i - 1; j++) {
            comparisons++;
            if (records[j].getStudentID() > records[j + 1].getStudentID()) {
                AttendanceRecord temp = records[j];
                records[j] = records[j + 1];
                records[j + 1] = temp;
                swaps++;
                swapped = true;
            }
        }
        if (!swapped) break; // Best-case O(n) optimization
    }
    isSortedByStudentID = true;
}

// Task 5 (Alternative): Insertion Sort with Empirical Counters
void insertionSortByStudentID(long &comparisons, long &shifts) {
    comparisons = 0; shifts = 0;
    for (int i = 1; i < recordCount; i++) {
        AttendanceRecord key = records[i];
        int j = i - 1;
        while (j >= 0) {
            comparisons++;
            if (records[j].getStudentID() > key.getStudentID()) {
                records[j + 1] = records[j];
                shifts++;
                j--;
            } else {
                break;
            }
        }
        records[j + 1] = key;
    }
    isSortedByStudentID = true;
}

// Task 6 (Primary): Linear Search O(n) — Works on Unsorted & Sorted Arrays
int linearSearchByStudentID(const string &targetID, long &comparisons) {
    comparisons = 0;
    for (int i = 0; i < recordCount; i++) {
        comparisons++;
        if (records[i].getStudentID() == targetID) {
            return i; // Found at index i
        }
    }
    return -1; // Not found
}

// Task 6 (Alternative): Binary Search O(log n) — Requires Sorted Array
int binarySearchByStudentID(const string &targetID, long &comparisons) {
    comparisons = 0;
    int low = 0, high = recordCount - 1;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        comparisons++;
        if (records[mid].getStudentID() == targetID)
            return mid;
        comparisons++;
        if (records[mid].getStudentID() < targetID)
            low = mid + 1;
        else
            high = mid - 1;
    }
    return -1;
}

Report Section 1 — Objective of the System

Purpose, Scope & Target Users

The Smart Attendance Tracking System (SATS) is designed for the Faculty of Computing, UTM to eliminate manual paper sign-in sheets and prevent proxy attendance through time-limited QR session tokens. In Assignment 1, the system models all entities using static, contiguous C++ arrays of objects loaded from persistent text files.

Target Actor 1: Lecturer (Admin) Registers students into students[], generates timed QR tokens in sessions[], sorts attendance rosters via Bubble/Insertion Sort, and exports reports.
Target Actor 2: Student (User) Submits QR session tokens to log or update attendance in records[] and searches personal attendance history with automatic percentage calculation.
Report Section 2 — System Synopsis & Business Rules

Core Functionalities & Validation Rules

  • 1. QR Token Validation & Expiry Rule: When a student scans a token, SATS searches sessions[] for a matching qrToken and verifies currentTime <= expiryTimestamp.
  • 2. Idempotent Duplicate Scan Handling: If a registered student scans the same valid QR code twice in one session, SATS locates their existing AttendanceRecord in records[] and updates the timestamp rather than inserting a duplicate row.
  • 3. Zero-Safe Attendance Percentage Formula: Calculated dynamically during UC04 as (presentCount / totalSessions) * 100.0, guarded against division by zero when totalSessions == 0.
